# Windows agent

The Windows agent runs in your session next to the Ollama desktop app and adds GPU and host stats, environment editing, restarts and logs.

Prerequisite: Node.js 18.15 or newer (`winget install OpenJS.NodeJS.LTS`).

Copy [`agent/windows/`](../agent/windows/) to the PC, open PowerShell in that directory, and run the installer **from the account that runs Ollama**. Run it in an admin PowerShell if you want it to add the firewall rule:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -AllowFrom 192.168.30.0/24
```

The installer:

- copies the agent to `%LOCALAPPDATA%\llama-paddock-agent`,
- writes `agent.json` with a generated token, readable only by you, and prints the token,
- registers a Scheduled Task, `llama-paddock-agent`, that starts the agent hidden at logon and restarts it if it crashes,
- when elevated, adds an inbound firewall rule for TCP 11435 from `-AllowFrom` (default: local subnet) on Private/Domain networks.

`uninstall.ps1` removes all of it and leaves your Ollama variables as they are.

**Why a logon task instead of a Windows service?** Ollama for Windows is a tray app that runs in your session and reads your account's environment variables. The agent has to live in that same session to restart it correctly. The trade-off is that the agent, like Ollama itself, only runs while you're logged in.

**Ollama on Windows only listens on `localhost` by default.** Once the agent is up, set `OLLAMA_HOST` to `0.0.0.0:11434` in the dashboard's Environment tab. The agent restarts Ollama with it. Also allow TCP 11434 from the dashboard host through Windows Firewall; the agent installer opens only its own port, 11435.

The Windows agent only ever shows or changes Ollama-related variables (`OLLAMA_*`, `CUDA_*`, `HIP_*`, `GGML_*`, …) plus any custom ones you add through the dashboard. It refuses to touch `Path`, `TEMP` and other system variables.

## Settings and updates

Settings live in `%LOCALAPPDATA%\llama-paddock-agent\agent.json`. Environment variables override values in this file.

| Setting | Default | Purpose |
|---|---|---|
| `PADDOCK_AGENT_TOKEN` | generated by installer | Required shared secret |
| `PADDOCK_AGENT_BIND` | `0.0.0.0` | Listen address |
| `PADDOCK_AGENT_PORT` | `11435` | Listen port |
| `PADDOCK_OLLAMA_APP` | `%LOCALAPPDATA%\Programs\Ollama\ollama app.exe` | Ollama desktop executable |
| `PADDOCK_DISK_PATHS` | empty | Extra drives or folders to report, comma-separated |

To update, copy the newer Windows agent files to the PC and re-run `install.ps1` from the same account. It keeps the existing `agent.json` and restarts the task. `-Token` and `-Port` initialize new configurations; they do not overwrite an existing file. If you change the port in `agent.json`, also pass the matching `-Port` when re-running the installer so its firewall rule uses that port.

The agent targets the standard Ollama desktop install, not an `ollama serve` process managed by NSSM or another Windows service wrapper. See [Troubleshooting](operations.md#troubleshooting) for firewall and GPU limitations.
